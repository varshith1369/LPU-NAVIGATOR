# Build order and completion gates

The sequence below follows the user's message. It records the original acceptance gates. Implementation has now reached a locally running map, API, account/admin workflow and retrieval assistant. Historical extraction, public OSM import, embedded database tests, graph tests and frontend compilation pass. Real campus entrance verification, native production database testing and cloud deployment remain open. ML is intentionally disabled. See README and verification.md for delivered behavior; a gate depending on unknown campus facts is not marked complete by writing code.

1. **Map data.** Preserve the historical source, transcribe the visible legend, record uncertainty and missing IDs, create the proposed master dataset. Gate: validate unique source IDs, null geography and traceable provenance. Current foundation: prepared and locally validated.
2. **Database.** Review and execute the PostGIS migration on a disposable database, write transactional seed/import scripts and integration tests. Gate: constraints reject invalid coordinates and provenance; repeat imports do not duplicate entries; migrations rebuild cleanly. Current foundation: schema proposed; runtime verification pending.
3. **Map.** Build the responsive React/Leaflet shell with explicit historical and geographic modes, details, category filtering and geolocation permission/error handling. Use a local repository adapter until the API exists. Gate: keyboard and mobile checks, correct attribution, no historical pixel positions treated as GPS.
4. **Search.** Search historical labels, proposed categories and printed IDs while separating them from current building codes. Add alias and fuzzy retrieval for current records. Gate: duplicate names remain individually identifiable, stale requests cannot overwrite newer results, empty and failed searches are clear.
5. **Backend.** Connect repository interfaces to validated, paginated REST endpoints and PostgreSQL. Add spatial nearby queries, caching and error contracts. Gate: database-backed API tests, query bounds, SQL injection defenses and verified source handling.
6. **Routing.** Import genuinely sourced path nodes/edges, implement Dijkstra/A*, attach entrances and display route evidence. Gate: disconnected, blocked, one-way and accessibility-unknown cases; distances come from real geometry; no-path state works. A usable real campus route is a prerequisite for claiming the navigation MVP complete.
7. **Auth.** Registration/login/logout, password reset integration, revocable sessions and user-owned favorites/history. Gate: hashing, expiry/revocation, rate limits, CSRF and cross-user access tests.
8. **Admin.** Location/category/facility/path/announcement management, evidence review, correction queue and audit logs. Gate: deny visitor/student/faculty admin mutations, approval transactions and concurrent-edit tests.
9. **AI.** Implement retrieval-first intents, source citations, provider abstraction and unsupported-answer handling. Gate: grounding, prompt-injection, absent-data and routing delegation tests. Historical answers must identify their age and uncertainty.
10. **ML.** Audit real data availability first. If insufficient, keep prediction absent and document the unmet gate. Otherwise train baseline and candidate models, evaluate on future-held-out observations and publish metrics before activation. No claim of a trained model without real data.
11. **Deployment.** Verify current provider requirements, build pinned artifacts, configure secrets, run migrations, TLS, backups/restore, health checks and smoke tests. Frontend on Vercel; API/AI and managed PostGIS on a selected compatible provider. Gate: working deployed URLs and verified production checks. Accounts/credentials and any paid provisioning remain external prerequisites.

At each implementation stage: run the relevant component, test its acceptance gate, correct failures and report evidence before advancing. Auth, Admin and AI follow a working navigation MVP. Verified campus data can be collected throughout; no code milestone bypasses factual verification.
