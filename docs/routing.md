# Routing

`backend/src/routing.mjs` implements Dijkstra, equivalently A* with an admissible zero heuristic. Costs are positive geography-derived meters. Blocked edges, unverified edges and prohibited one-way traversal are excluded. Reversing a bidirectional edge reverses its GeoJSON coordinates. Accessibility-required queries exclude every edge whose accessibility is not explicitly true.

Strict routing requires reviewed entrance associations and active operating status. Search enumerates entrance combinations and chooses the shortest connected path. The UI also offers approximate guidance (`allow_approximate: true`): if an entrance is missing, it selects the nearest sourced path node within 150 metres of the building's sourced point. It never draws a line through buildings from the point to that path, creates an entrance record, or merges disconnected graph components. Results prominently report both straight-line access gaps as unverified. Distance and time cover mapped edges only. Walking time uses a recorded edge time or a transparent 1.2 m/s estimate. The current instruction list reports continuation distances; richer turn-by-turn and indoor navigation remain future work.

The imported OSM snapshot contains 261 pedestrian segments with approximate status. No entrances were established by the supplied evidence. Approximate guidance can therefore show connected nearby paths, but does not claim door-to-door access. Accessibility-required requests never use the nearby-node fallback. Integration tests cover the reported Management–Technology journey, strict rejection, accessibility rejection and absence of newly invented entrance records, alongside isolated synthetic graph tests.
